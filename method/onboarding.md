# Onboarding — when there is no instance yet

> **Read when** `instance/` is missing, or holds no `index.md`. That is the whole trigger, and
> it fires at most once on a machine.
> **Do not read** otherwise. An instance that answers is an instance that exists, and re-reading
> this file against a working corpus can only produce a second one.

---

## The rule that bounds everything below

**Notice, say it in one sentence, offer, and wait.**

An absent instance is discovered at § *Step 0* of `organization.md` — which is to say in the
first seconds of a session that was opened to do something else. Nothing here authorises
interrupting that. The agent states the fact, offers to fix it, and stops:

> There is no instance here yet, so I do not know your language, your register or your
> conventions. Ten minutes of questions and I can write a first one — or I carry on without it
> and we do this later.

If the answer is *later*, carry on **and say so plainly**: working without an instance is
working without the identity rules, and that is a fact the developer should hear once rather
than discover in the tone of the third answer.

⚠ This is the same discipline as offering to install a missing runtime (`bootstrap.md`
§ *A prerequisite the agent resolves*): the offer stays an offer, because the cost falls on
someone else's machine and someone else's session. A file that starts an interview unasked has
become a second starting point that wins over the request — the exact failure this method
removed from per-tool trigger files.

## What the interview is for, and where it stops

It produces **two files and no more**: an identity file, and the `index.md` that declares it.

The questions are already written, and not by this file — `organization.md` § *Step 0* states
exactly what the instance is read for:

> who is being worked with and how to address them — the language to answer in, the register,
> whether the person works alone or in a team.

**Ask that, and stop there.** Four subjects, a handful of questions, ten minutes.

⚠ **Do not collect conventions.** It is tempting — the corpus is empty, the developer is
available, and asking about their C# habits feels like the same conversation. It is not. A
convention written before its first use is a guess that nobody will contradict, and it arrives
in a file that a trigger will open with full authority. Conventions are written **when a trigger
first fires and the corpus turns out to have nothing to say** — one file, at the moment its
absence is felt.

## What must come out of it

**An identity file.** Whatever it is called — `profile.md` is a common choice and nothing more
than that. It carries the answers, in the developer's own terms, and it opens with a line saying
it was drafted in an onboarding interview and is expected to be corrected. It will be: the first
version of an identity file is always slightly wrong, and it is much easier to fix a text than to
produce one.

**An `index.md`.** It declares what exists in the folder and, for each file, **when it is read**.
On day one it has a single line — the identity file, read always and first. That is not a poor
index, it is a correct one, and `corpus.md` shows exactly what it looks like.

⚠ The interesting question arrives with the **second** file, not the first: a line that says
*when* to read something has to be decidable before the file is opened, and getting that wrong
is how a corpus quietly becomes unusable. `corpus.md` is where that is written, and it is read
then rather than now — there is nothing to decide about a one-line index.

⚠ **The identity file's name is declared by the index, never assumed by the method.** Anything
here that hard-coded a filename would be wrong on the first machine that chose another. The
method declares the slot and its timing; the instance declares what fills it.

⚠ **Show both drafts before writing them.** These two files decide the first sentence of every
future session, and they are being written by the party who has known the developer for ten
minutes. Read them out, take the corrections, then write.

## After that

The instance grows one file at a time, and only ever the same way: a trigger fires, the corpus
has nothing to say about it, and that gap is what a new file answers. Each addition is declared
in `index.md` **in the same gesture** — a file no index names is read by nobody, which is not a
figure of speech but a measured outcome. How to write that declaration is `corpus.md`.

There is nothing else to run, and this file is not read again.
